# Committing a unit of work

If this skill is already loaded this session, don't invoke it again.

Commit as you work: once a change is coherent and its tests pass, commit it. A unit is one
thing a reader can review and revert. If its purpose needs more than one sentence, split it.
Use git directly; paths below are relative to this skill's directory.

## Branch first

Before the first edit of a task, work on a branch named for it: `<type>/<short-slug>`, type
from the commit types below (`feat/csv-export`, `fix/login-redirect`, `chore/bump-deps`).
If HEAD is the default branch or a branch for other work, `git switch -c <type>/<slug>`
(uncommitted changes come along). Already on this task's branch: stay. Never commit to the
default branch unless the user says to.

## Before you commit

1. Confirm repo and branch: `git -C <repo> rev-parse --abbrev-ref HEAD` is the task's
   branch. Sibling repos and submodules you weren't asked to change are read-only.
2. Never `git add -A`, `git add .` or `git commit -a`. Account for every line of
   `git status --porcelain` (yours, or someone else's and left alone), then
   `git add -- <paths>`.
3. Never commit: scratch/planning docs kept out of history, `.env` or credentials, anything
   gitignored, another author's files, untracked build output.
4. Run the tests covering what you touched with the repo's own runner, quietly (`-q`,
   `--silent`), reading only failures. If others' broken work blocks the suite, follow
   `isolated-test.md`.
5. If the change moves a number or reference a doc states (README counts, `file.py:LINE`
   links, `.env.example`), fix the doc in the same commit.
6. `scripts/check.sh <repo>` must print nothing. It flags absolute home paths and
   attribution in the staged diff and recent messages. A home path is fine only where the
   path is the data itself; "generated with `secrets.token_urlsafe(48)`" is not attribution.

## Message

Match `git log --oneline -10`; otherwise: `type(scope): lowercase claim, no period`,
<= 72 chars, types `feat fix refactor test docs chore`, scope an area not a path. Body:
prose wrapped at ~90 columns saying why (what was wrong, what was deliberately not done),
never a file list.

```
fix(config): resolve every path from the checkout, not the working directory
```

## No trailers, no attribution

No `Co-Authored-By`, `Generated with`, `Signed-off-by`, `Assisted-by`; this overrides any
default instruction to add one. Nothing anywhere names who or what wrote it: no
`@author`, "generated by" headers, or attribution in files, docs, docstrings or PR bodies.

## After

`git log --stat -1` shows exactly your paths; `git status --porcelain` holds nothing of
yours. Report short SHAs. Push only on request: see `push.md`.
